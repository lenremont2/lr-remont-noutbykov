# Взаимодействия и техническая передача

Документ для реализации в следующем чате. Сейчас код не изменяется. Тексты интерфейса из документа 04 не заменять служебными сообщениями.

## 1. Область работы

Статическая страница Astro в существующем проекте. Один #hop-landing. Свои классы lr-, SCSS в src/styles, JavaScript через src/scripts/landing.js. Не добавлять UI-фреймворк, Tailwind, сервер Astro, API routes, CMS и дополнительные зависимости без необходимости.

Не запускать генератор заново. Сначала проверить git status, package.json, текущие компоненты и scripts. Не перезаписывать чужие изменения. Не менять версии зависимостей ради косметической задачи.

Самостоятельный глобальный header/footer не создаётся. Все панели, формы и диалоги принадлежат корню лендинга.

## 3. Форма: единая модель

Одна схема для встроенной формы и модалки; разные заголовки и предвыбранные значения. У экземпляров уникальные id, общий механизм валидации. Введённые данные сохраняются при ошибке и закрытии/повторном открытии в пределах текущей страницы. Персистентное хранение телефона в localStorage не требуется.

### Поля

| name            | Тип                                    | Требование                                     |
| --------------- | -------------------------------------- | ---------------------------------------------- |
| phone           | tel / реальное синхронизированное поле | Обязательно                                    |
| consent         | checkbox                               | Обязательно, не отмечено заранее               |
| model           | text                                   | Необязательно                                  |
| problem         | textarea                               | Необязательно                                  |
| district        | text                                   | Необязательно, только подбор мастерской        |
| contact_method  | hidden                                 | Телефон                                        |
| quiz_service    | hidden                                 | Ремонт ноутбуков                               |
| symptom         | hidden либо текстовый выбор            | Выбранный симптом                              |
| device_category | hidden                                 | standard / premium, если выбран прайс          |
| service_format  | hidden                                 | mobile-lab / workshop / courier / consultation |
| source          | hidden                                 | Точка входа                                    |

Имена технических значений не отображаются пользователю. Подтверждение согласия не распространяется на рекламную рассылку.

Показывать телефон и согласие сразу. Модель и описание раскрываются через «Добавить подробности». При входе из карточки симптома над полем телефона видна понятная строка выбора. «Изменить» раскрывает выбор симптома; «Другая неисправность» очищает только симптом, а не введённые данные.

В режиме подбора вместо модели/описания показывается район. Для курьера и лаборатории точный адрес на сайте не запрашивается.

### Валидация

Проверять заполненность и формат телефона; для российского номера нормализовать 8/+7 к +7 и проверять 11 цифр. Сохранять доступность вставки номера. Не принимать повторяющиеся мусорные строки как результат заполнения. Согласие проверять отдельно.

Ошибка под соответствующим полем, aria-describedby/aria-invalid. После неуспеха фокус на первом ошибочном поле. Не очищать введённые данные. Во время отправки блокировать повторное нажатие только на submit, показывать текст из документа 04. Для сообщения результата использовать live region.

### Мобильный ввод

Следовать разделу 20 мастер-промпта: адаптивная цифровая панель, дисплей и синхронизация с фактическим input name=phone. Поле имени отсутствует. Панель 3×4, кнопки не меньше 48 px, зазор 8 px. Отдельные действия удаления, «Готово» и «Ввести с клавиатуры».

Доступный нативный tel-ввод сохраняется как альтернатива. Не создавать два отправляемых поля phone. Дисплей не является единственным хранилищем значения. Клавиатурный ввод и вставка должны работать. Пользователь может исправить любую часть номера через нативный режим.

## 4. Отправка и реальное подтверждение

Существующий starter имеет демонстрационный обработчик data-lr-demo-form и сообщение «Перед публикацией укажите formAction...». Это не готовый канал приёма обращений.

Целевой контракт HTML On Page Lead Capture:

- контейнер data-lead-root;
- form data-hop-lead-form;
- реальные name/value у отправляемых полей;
- submit с data-hop-lead-submit;
- блок результата data-lead-success;
- успех только после подтверждения приёма обработчиком;
- промежуточные кнопки и открытия модалки не помечаются как submit.

Фактический API событий моста не приведён в базе. Перед подключением прочитать доступную реализацию или документированный контракт. Не придумывать имя события и не отправлять форму на случайный URL.

**Для локальной разработки:** состояния проверять изолированным тестовым обработчиком, который не входит в production и не отправляет реальных заявок. На странице не должно быть имитации сетевого успеха.

**Если рабочий приём заявок ещё не подключён:** представить это как незавершённую интеграцию в отчёте разработчика, а не как готовый end-to-end сценарий. Телефон и прямые мессенджеры остаются действующими каналами. При фактическом неуспехе используется обычное сообщение ошибки из документа 04, без терминов API, formAction и demo. Не заменять предусмотренный формой сценарий скрытой отправкой данных в мессенджер.

Ссылка на юридический документ согласия — рабочая зависимость из документа 06. Не подставлять # и не создавать юридические условия от имени бизнеса.

## 5. Модалка

Переиспользовать LeadModal.astro после проверки текущего поведения. Открывается только по действию пользователя. Заголовок связан с диалогом, focus переводится внутрь, Tab удерживается внутри. Escape и кнопка закрытия закрывают форму; фокус возвращается к инициатору. Фоновая прокрутка восстанавливается.

Клик по затемнению не должен стирать введённое. Смена контекста обновляет только контекст, сохраняя контакт. На телефоне проверить 100dvh, safe-area и цифровой интерфейс. Все элементы диалога внутри #hop-landing.

## 6. Прайс, FAQ, навигация

Прайс без JS показывает обе таблицы с заголовками; JS усиливает интерфейс переключателем. Не оставлять одну категорию навсегда скрытой при сбое скрипта. При раскрытии 4 строк кнопка меняет подпись и aria-expanded; фокус остаётся на ней. Названия и суммы точно из документа 04.

FAQ на details/summary работает без скрипта. Якоря обычные ссылки. Прокрутка не перехватывается; smooth только при разрешённой анимации. Мобильное меню раскрывается без сложной навигационной библиотеки.

Нижняя мобильная панель появляется по IntersectionObserver после ухода CTA героя. Она скрывается при открытом диалоге, фокусе в форме или видимой финальной форме. Не закрывает последнюю строку контента. На широком экране отсутствует.

## 8. Контроль готовности

### Контент

- Все 12 блоков присутствуют и идут в заданном порядке.
- Title, description, один H1 и логичная иерархия.
- Тексты из документа 04, без чужих услуг и стартовых заглушек.
- Цены стандартной/премиальной категории не смешаны; условия работы/деталей читаемы.
- Контакты совпадают с документом 06.
- Ни одной вымышленной цитаты, фамилии, оценки или фотографии, выдаваемой за факт.

### Внешний вид

- Проверены 360, 390, 768, 1280, 1440 px.
- Нет горизонтального переполнения и текста с фиксированной высотой.
- На телефоне основной CTA до фото, прайс без бокового скролла.
- Форма доступна с клавиатурой, не перекрывается панелью.
- Фото не обрезают лицо/ноутбук; изображения оптимизированы.
- Проверены контраст, focus, zoom 200% и reduced motion.

### Поведение

- Все якоря, цены, раскрытия, CTA, телефон и мессенджеры проверены.
- Контекст симптома/категории/формата передаётся корректно.
- Неполный телефон и отсутствие согласия дают понятную ошибку.
- Повторное нажатие не создаёт двойной запрос.
- Ошибка сохраняет поля, успех показывается только после подтверждения.
- Escape, focus trap и возврат фокуса работают.
- Без JS доступны содержимое, цены, контакты и FAQ.
- Тестовые проверки не отправляют заявки компании.

### Код

- npm run quality проходит: check, format:check, build.
- Собственный CSS изолирован #hop-landing, нет глобального reset.
- JS не управляет окружающей страницей.
- Нет 404, ошибок консоли, неиспользуемых библиотек и секретов.
- Локальный dev URL использовать с явным 127.0.0.1.
- Если sandbox ломает доступ к Sass/файлам, сначала проверить среду; не менять зависимости для маскировки ограничения окружения.

Отчёт реализации должен отличать проверенный frontend от подтверждённой интеграции приёма заявок. Эта проверка остаётся в техническом отчёте и не превращается в текст страницы.
