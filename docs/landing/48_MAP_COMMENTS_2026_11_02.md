# Карты и CTA способов ремонта — 02.11.2026

Последние комментарии пользователя заменяют решение из документа 45: вместо списка адресов в секции `#lr-locations` теперь одна заглушка карты мастерских.

Использован существующий `LeadModal` на нативном `<dialog>`. Одно окно переключает два контейнера: мастерские или выбор адреса. Отдельный комплект форм и библиотека карт не добавлялись. Изменение общего `RepairFormats` применяется также к страницам брендов, неисправностей и MacBook.

| CTA                | Карта        | Контекст `data-format` на dialog |
| ------------------ | ------------ | -------------------------------- |
| Вызвать мастера    | Выбор адреса | `at-home`                        |
| Вызвать мастерскую | Выбор адреса | `mobile-lab`                     |
| Выбрать мастерскую | Мастерские   | `workshop`                       |
| Вызвать курьера    | Выбор адреса | `courier`                        |

Кнопки открывают окно, а без JavaScript ведут к существующей форме. Закрытие: крестик, Escape или клик вне окна; фокус возвращается на исходную кнопку. Нижняя мобильная панель удалена по последующему указанию пользователя.

## Подключение плагина

| Контейнер                 | Место                  | Тип карты    |
| ------------------------- | ---------------------- | ------------ |
| `#lr-map-workshops`       | Секция адресов главной | Мастерские   |
| `#lr-map-workshops-modal` | Окно карты             | Мастерские   |
| `#lr-map-address`         | Окно карты             | Выбор адреса |

Внутреннее содержимое соответствующего `data-lr-map-slot` нужно заменить результатом выполнения реального шорткода. Сам контейнер и его ID сохраняются. В Astro шорткоды WordPress не исполняются; имена шорткодов, параметры и публичный API плагина в проекте не заданы и здесь не выдумываются.

На `dialog[data-lr-modal="map"]` перед открытием устанавливаются `data-format` и `data-source`. Внутри виден один `data-lr-map-view`; второй скрыт. Плагину нужно инициализировать карту после открытия окна или обновлять её размеры при открытии (нативное событие `toggle`), а также после переключения видимой карты.

Мастерские в секции и окне — два отдельных экземпляра. При подключении проверить поддержку нескольких экземпляров и отсутствие повторных ID внутри результата шорткода. Выбор точки, адрес, геокодирование и передача результата в заявку остаются ответственностью реального плагина: местный макет их не имитирует. Размещение в WordPress и правки PHP не выполнялись.

## Проверка

Статические проверки: четыре CTA с правильными типами карт; одно окно и оба контейнера присутствуют на всех 49 дочерних страницах. Поведение проверяется скриптом `artifacts/map-comments-2026-11-02/verify.mjs`: пять размеров экрана, четыре формата, три способа закрытия, возврат фокуса, запрет фокуса на фоновой форме, отсутствие горизонтального переполнения и работа обычной формы после закрытия карты. Результат запуска сохраняется в соседний `results.json`.

Настоящие шорткоды и поведение сторонней карты до её подключения не проверены.

## Уточнение места в квизе — 05.11.2026

Уточнение от 06.11.2026: контейнеры обеих карт в квизе занимают ширину панели и имеют высоту `clamp(260px, 40dvh, 320px)`, включая окно квиза. При подключении WP содержимое карты должно заполнять этот контейнер. Оформление реальной карты, параметры плагина, выбор точки и взаимодействие с квизом настраиваются при переносе и синхронизации страницы с WordPress. Сейчас изменены только размеры мест под карты; карты вне квиза сохраняют прежние размеры.

После выбора способа ремонта добавлен отдельный шаг, перед подготовкой заявки и телефоном:

- `workshop` — место карты мастерских `#lr-quiz-map-workshops` и выбор конкретного адреса из существующего справочника;
- `mobile-lab`, `at-home`, `courier` — место карты выбора адреса `#lr-quiz-map-address`, адрес выезда/забора и применимое пожелание о месте ремонта;
- `consultation` — шаг места пропускается.

Подтверждённые данные передаются в существующие `workshop_id`, `visit_address`, `requested_repair_place` формы заявки и показаны в итоговой сводке. Возврат назад сохраняет выбор и введённый телефон. Поля места в финальной форме не дублируются визуально.

По указанию пользователя проверены исходники плагина на `testing-gutenberg.local`: Dynamic Map — Ленремонт 2GIS 1.1.1 регистрирует `[dmap]` и `[lenremont_workshops_map]`. Рендерер допускает только один экземпляр на странице; это карта просмотра мастерских, без подтверждённого публичного интерфейса передачи выбора в квиз. Плагин `on_oprosnik` на этом стенде не установлен.

В HTML production-образца роботов-пылесосов подтверждён отдельный iframe выбора адреса сервиса `maps.lenremontn8n.ru` и скрипты `on_oprosnik/js/map-contract.js`, `delivery-ui.js`. Эти скрипты и сам сервис недоступны из текущей среды. Контракт iframe не выдумывается, WordPress и плагин не изменяются. В Astro остаются явные существующие заглушки карт и работает выбор мастерской/ввод адреса. Выбор точки, геолокация и передача координат через реальную карту пока не подключены и не проверены.

Проверки нового шага: сборка 56 страниц и Astro check без ошибок/предупреждений; тесты квиза, форм, адресных полей, телефона, контекста и 49 дочерних страниц прошли. Проверены четыре формата, пропуск для консультации, обязательность адреса/мастерской, итоговая сводка, возврат назад и сохранение телефона. Общий `quality` останавливается на прежних 89 файлах форматирования. В браузере подтверждён начальный экран с пятью шагами; дальнейшую интерактивную и мобильную проверку прервали сбои подключения.
